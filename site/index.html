PROJECT OVERVIEW

The telephone network,
for autonomous AI.

Why this exists, what it aims to make possible, and what remains experimental.

The project is developing an open-source communications platform that enables autonomous AI agents to make telephone calls over the existing global telephone network.

The goal is not to build another AI assistant or another softphone. It is to give autonomous AI agents access to the telephone network as a standard, secure, and programmable capability.

WHY THIS EXISTS

A real phone call.
On an agent's terms.

Give the task to an agent. It should obtain permission, connect to the telephone network, hold a conversation and return a grounded result. The telecoms complexity stays out of the way.

↗
01 / ACCESS

Call, don't configure.

A single interface for agents. No SIP accounts, softphones, dialplans, or carrier credentials in your model's context.

◉
02 / AUDIO

Built for conversation.

Real-time, bidirectional audio is the aim. Listen, speak, respond to interruption, and know when a person has answered.

⌁
03 / EVIDENCE

Trust the event, not the guess.

Sequenced events, explicit call states, and attributed results. An agent's claim is never confused with network-confirmed reality.

◇
04 / CONTROL

Bounded by design.

Destination permissions, maximum durations, identity-bound credentials, and independently verified termination are essential.

THE CALLING SYSTEM

One agent interface.
Two telecom routes.

Design target: a human authorises a bounded task, the agent satisfies any managed x402 payment requirement, and the chosen provider executes the call through controlled FreePBX/PJSIP call policy. Operators may instead supply their own Asterisk infrastructure without managed payments.

01 / AGENT

Discover

Read capability flags; request human permission for one destination. No SIP credentials in model prompts.

02 / ACCESS

Authorise and pay

Managed calling aims to use x402; BYOT needs no managed payment. Neither payment nor speech authorises an arbitrary route.

03 / TELEPHONY

Connect and converse

Use the selected FreePBX/PJSIP connection to establish a bounded call and carry two-way speech. Readiness and routing checks reduce avoidable failures, but do not guarantee an answer.

04 / EVIDENCE

Report accurately

Separate network state, what was heard and what the destination actually confirmed. Never manufacture success.

THE DEVELOPER EXPERIENCE

Four steps.
One conversation.

What the finished service will feel like to an autonomous agent. The laboratory currently simulates the calling boundary.

01

Describe the task

Who to call, why, which agent is acting, and the maximum duration.

02

Receive a call ID

Use idempotency keys so retries don't create multiple calls.

03

Stream the conversation

Audio flows separately from the control API; events tell the agent what changed.

04

Return the evidence

Track status, usage, and what the agent observed, without overstating certainty.
